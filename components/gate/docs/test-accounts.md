# Test Accounts

TrinityCore reference-vector accounts with known passwords and verifiers.
Generated by the TrinityCore BnetSRP6v2 reference tool and byte-for-byte
verified against the C++ reference implementation.

All accounts have the same fixed test salt (`00 … 00`, 32 bytes) and 15000
PBKDF2 iterations. Verifiers match the reference implementation's
`BnetSRP6v2<SHA256>` output.

Seed with:

```bash
podman exec -i tavern-db psql -U tavern -d tavern < docs/test-accounts.sql
```

## Integration Test Accounts

Integration tests create throwaway accounts at runtime using
`unique_email("tag")` → `{milestone}-{tag}-{uuid}@example.com`. Each test
cleans up its own rows. These accounts do not need to be pre-seeded.

## Test Signing Key

All tokens are signed with `keys/signing.pem` (kid: `tavern-1`, environment:
`demo`). The oauth-server logs a warning when this key is used. Generate a
production key with:

```bash
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out keys/signing.pem
```

## Manual oauth2c Flow

1. Start the database: `podman start tavern-db`
2. Start the account server:

   ```bash
   DATABASE_URL=postgres://tavern:tavern@localhost:5432/tavern \
     cargo run -p account-server
   ```

3. Start the OAuth server:

   ```bash
   DATABASE_URL=postgres://tavern:tavern@localhost:5432/tavern \
     ISSUER_URL=http://localhost:8080 \
     cargo run -p oauth-server
   ```

4. Run oauth2c against the OAuth server:

   ```bash
   oauth2c http://localhost:8080
   ```

5. Log in with one of the reference accounts above (e.g., `test@example.com` /
   `password`).
